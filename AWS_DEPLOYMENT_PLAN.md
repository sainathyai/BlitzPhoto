# AWS Deployment Plan - BlitzPhoto

## Overview

This document outlines the deployment strategy for BlitzPhoto on AWS us-west-2.

## Architecture

```
┌─────────────────┐
│   CloudFront    │ (Frontend CDN)
└────────┬────────┘
         │
    ┌────▼────┐
    │   S3    │ (Static Frontend)
    └─────────┘

┌─────────────────┐
│   ALB (443)     │ (Load Balancer)
└────────┬────────┘
         │
    ┌────▼────┐
    │  ECS    │ (Backend Containers)
    │ Fargate │
    └────┬────┘
         │
    ┌────▼──────────────────────┐
    │  RDS PostgreSQL           │
    │  S3 (uploads/thumbnails)  │
    │  SQS (upload queue)       │
    └───────────────────────────┘
```

## Deployment Strategy

### 1. Backend (Spring Boot)
- **Platform**: ECS Fargate (serverless containers)
- **Container Registry**: Amazon ECR
- **Load Balancer**: Application Load Balancer (ALB)
- **Scaling**: Auto-scaling based on CPU/memory
- **Health Checks**: ALB health checks + Spring Boot actuator

### 2. Frontend (React/Vite)
- **Platform**: S3 + CloudFront
- **Build**: Static files generated by Vite
- **CDN**: CloudFront for global distribution
- **HTTPS**: ACM certificate

### 3. Infrastructure
- **VPC**: Already provisioned via Terraform
- **RDS**: Already provisioned (PostgreSQL)
- **S3**: Already provisioned (uploads, thumbnails)
- **SQS**: Already provisioned (upload queue)

## Prerequisites

1. AWS CLI configured with credentials
2. Docker installed and running
3. Terraform infrastructure already deployed
4. ECR repository created
5. ACM certificate (optional, for custom domain)

## Deployment Steps

### Phase 1: Infrastructure Setup
1. Update Terraform to add ECS resources
2. Create ECR repositories
3. Create ALB and target groups
4. Update IAM roles for ECS tasks

### Phase 2: Backend Deployment
1. Build Docker image
2. Push to ECR
3. Create/update ECS task definition
4. Deploy ECS service
5. Update ALB target group

### Phase 3: Frontend Deployment
1. Build React app with production config
2. Upload to S3
3. Invalidate CloudFront cache
4. Update environment variables

### Phase 4: Verification
1. Test backend health endpoint
2. Test frontend access
3. Verify upload functionality
4. Check CloudWatch logs

## Cost Estimation

**Development Environment:**
- ECS Fargate: ~$15-30/month (0.5 vCPU, 1GB RAM, minimal traffic)
- ALB: ~$16/month
- CloudFront: ~$1-5/month (minimal traffic)
- S3: ~$1/month
- **Total: ~$35-55/month**

**Production Environment:**
- ECS Fargate: ~$50-200/month (scaling based on load)
- ALB: ~$16/month
- CloudFront: ~$10-50/month (depending on traffic)
- S3: ~$5-20/month
- **Total: ~$100-300/month**

## Security Considerations

1. **HTTPS Only**: All traffic via HTTPS
2. **Security Groups**: Restrict access to necessary ports only
3. **IAM Roles**: Least privilege principle
4. **Secrets Management**: Use AWS Secrets Manager for sensitive data
5. **VPC**: Backend in private subnets, ALB in public subnets
6. **WAF**: Consider AWS WAF for DDoS protection (production)

## Monitoring & Logging

1. **CloudWatch Logs**: Application logs
2. **CloudWatch Metrics**: CPU, memory, request count
3. **ALB Access Logs**: Request logging
4. **ECS Service Events**: Deployment and scaling events

## Rollback Strategy

1. **ECS**: Keep previous task definition, update service to use it
2. **Frontend**: Keep previous S3 version, update CloudFront origin
3. **Database**: Use RDS snapshots for critical rollbacks
